# Phase 2 Implementation: Real-Time Data Backend

The real-time backend comprises four logical microservices deployed across six containers using Docker Compose for reproducible Infrastructure as Code. Custom Dockerfiles use `python:3.11-slim` and `apache/spark:3.5.1-python3` as base images for Ingestion and Processing, while the Message Broker runs a two-node Kafka cluster (KRaft mode) and Visualization uses official Grafana.

Service orchestration relies on container health checks. An ephemeral initialization container waits for both brokers to report healthy, creates the `raw_data` and `aggregated_data` topics (3 partitions, replication factor 2), and provisions SASL/PLAIN ACLs. The Ingestion service streams synthetic Swiss IoT sensor payloads with connection retry logic. The PySpark Structured Streaming service consumes the stream, validates ISO 8601 timestamps, and executes row- and column-level filtering. It then transforms records — normalizing temperature from Celsius to Fahrenheit and deriving a categorical pressure band (low/normal/high) — before computing sliding-window aggregations (5-minute window, 60-second slide) over these fields, with checkpointing for fault-tolerant state recovery. Aggregated metrics are emitted to Kafka and visualized live in Grafana.

The system was verified locally. Health status checks confirmed inter-service communication, integration tests validated end-to-end data flow, and security tests confirmed that unauthorized writes are blocked by Kafka ACLs. Complete source code resides in the accompanying GitHub repository.
